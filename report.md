## 1. Введение

Цель задачи - разработка и реализация последовательной и параллельной версий алгоритма для суммирования элементов массива. Дополнительно необходимо реализовать тесты для проверки их корректности и провести сравнительный анализ эффективности обоих подходов с использованием реальных данных.

## 2. Постановка задачи

На вход подается вектор из челых чисел.
Требуется определить сумму элементов этого вектора.

Тип входных данных:

```cpp
using InType = std::vector<int>;
```

Тип выходных данных:

```cpp
using OutType = int;
```

## 3. Базовый алгоритм (Sequential)

Основной принцип работы заключается в последовательном обходе всех элементов вектора и суммировании их значений в общую переменую:

```cpp
int sum = 0;
for (int val : GetInput()) {
  sum += val;
}
```

## 4. Схема распараллеливания

### Краткое описание

Алгоритм распараллеливается по схеме распараллеливания по данным. Исходный вектор делится на равные сегменты между всеми процессами. Каждый процесс выполняет суммирование своей части. Затем эти локальные суммы объединяются в общую.

### 4.1. Предварителльные действия

```cpp
int rank = 0;
int mpi_size = 0;

MPI_Comm_rank(MPI_COMM_WORLD, &rank);
MPI_Comm_size(MPI_COMM_WORLD, &mpi_size);

auto &input = GetInput();
size_t input_size = input.size();
```

**Описание:**
На первом этапе определяется количество доступных процессов и текущий ранг процесса.
Далее сохраняется ссылка на входной вектор и сохраняется его размер.

### 4.2. Алгоритм базового распределения

```cpp
size_t base_elements_per_process = input_size / mpi_size;
size_t extra_elements = input_size % mpi_size;
```

**Описание:**
Переменная base_elements_per_process хранит минимальное количество элементов, которое получит каждый процесс при равномерном делении.
Переменная extra_elements хранит остаток от деления — количество "лишних" элементов, которые не распределяются равномерно.

### 4.3. Определение количества элементов для текущего процесса

```cpp
bool this_process_gets_extra = (static_cast<size_t>(rank) < extra_elements);
size_t elements_for_this_process = base_elements_per_process + (this_process_gets_extra ? 1 : 0);
```

**Описание:**
Переменная this_process_gets_extra — булево значение, которое указывает, получит ли текущий процесс дополнительный элемент. Если rank процесса меньше количества лишних элементов, то процесс получит один дополнительный элемент.
Далее определяется точное количество элементов, которое должен обработать текущий процесс.


### 4.4. Определение границ обработки для текущего процесса

```cpp
size_t start_index = 0;
if (this_process_gets_extra) {
  start_index = base_elements_per_process * rank + rank;
} else {
  start_index = base_elements_per_process * rank + extra_elements;
}
size_t end_index = start_index + elements_for_this_process;
```

**Описание:**
Переменная start_index хранит индекс первого элемента, который обработает текущий процесс, она определяется в зависимости от того, получает ли текущий процесс дополнительный элемент.
Переменная end_index хранит индекс элемента, на котором текущий процесс прекращает обработку (граница не включена).

### 4.5. Вычисление локальной суммы

```cpp
int local_sum = 0;
for (size_t i = start_index; i < end_index && i < input_size; i++) {
  local_sum += input[i];
}
```

### 4.6. Объеденение в конечный результат
```cpp
int global_sum = 0;
MPI_Allreduce(&local_sum, &global_sum, 1, MPI_INT, MPI_SUM, MPI_COMM_WORLD);
```

**Описание:**
Функция MPI_Allreduce() выполняет коллективную операцию редукции — она собирает локальные суммы со всех процессов, складывает их и распределяет результат обратно всем процессам

## 8. Заключение

Разработаны реализации алгоритма суммирования элементов вектора для последовательного выполнения (SEQ) и с применением интерфейса передачи сообщений (MPI). На основании проведенных экспериментальных исследований и их анализа можно сделать следующие выводы:

1. Корректность: алгоритмы успешно выполняют вычислительные операции, включая обработку больших объемов данных.
2. Производительность и масштабируемость: с увеличением количества процессов наблюдается рост времени выполнения, что обусловлено низкозатратными вычислениями, которые не перекрывают накладных расходов на организацию передачи сообщений между процессами с использованием функции MPI_Allreduce().

Этот вывод позволяет предположить, что при увеличении объема суммируемых данных эффективность MPI-реализации возрастет, поскольку накладные расходы на передачу сообщений останутся неизменными, в то время как вычислительные затраты увеличатся.
